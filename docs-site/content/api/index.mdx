Everything below is re-exported from the crate root, so `use datatable::{Table, Value};` is all most code needs.

## Types

| Item | Kind | Description |
| --- | --- | --- |
| [`Table`](/api/table/) | struct | The table: a shared handle to an array part and a hash part. |
| [`TableRef`](/api/table-ref/) | struct | A read-only borrowed view of a table, from `Table::borrow`. |
| [`Value`](/api/value/) | enum | A dynamic value: nil, boolean, integer, float, string or table. |
| [`Key`](/api/key/#key) | enum | An owned, always-valid key. |
| [`KeyRef`](/api/key/#keyref) | enum | A borrowed key used for lookups. |
| [`Error`](/api/error/) | enum | Why a table operation failed. |
| [`Result`](/api/error/#result) | type alias | `std::result::Result<T, Error>`. |

## Modules

The items are also reachable through their modules: `datatable::table`, `datatable::value`, `datatable::key`, `datatable::iter` and `datatable::error`. The crate root is the recommended path.

## Conventions on these pages

- Signatures are shown as declared. `K: AsKey` means any key type; `V: Into<Value>` (or `impl Into<Value>`) means any value type.
- **Complexity** badges give the cost in terms of `n`, the number of elements involved.
- Methods that take `&self` and change the table do so through interior mutability; see [Core Concepts](/getting-started/core-concepts/#borrowing-rules).
