## What is datatable?

Rust gives you a precise tool for every shape of data: `Vec` for lists, `HashMap` for lookups, structs for records. That precision is usually what you want. Sometimes it is not: configuration loaded at runtime, a scripting layer, test fixtures, JSON-like documents, or prototyping before you know the final shape.

`datatable` fills that gap with a single type, [`Table`](/api/table/). One table can hold a numbered sequence and named fields side by side, store values of six different types, and nest other tables inside it.

```rust
// file: src/main.rs
use datatable::{table, Table, Value};

let player = Table::new();
player.set("name", "Ada")?;           // a named field
player.set("level", 7)?;
player.push("sword")?;                // player[1]
player.push("shield")?;               // player[2]

assert_eq!(player.len(), 2);          // the sequence part
assert_eq!(player.field_count(), 4);  // every field
assert_eq!(player.get("name"), Value::from("Ada"));

let scores = table![42, 7, 19];
scores.sort()?;
assert_eq!(scores.concat(", ")?, "7, 19, 42");
```

The design is inspired by tables in the Lua language, which use one structure for every kind of collection. `datatable` borrows that idea and much of Lua's `table` library, but it is a Rust library with Rust semantics, not a Lua implementation. [Coming from Lua](/guides/coming-from-lua/) lists the differences.

## Main features

| Feature | Description |
| --- | --- |
| [One type, many shapes](/getting-started/core-concepts/) | Use the same `Table` as a list, a dictionary, a record or a set, or all of them at once. |
| [Sequence operations](/guides/sequences/) | `push`, `pop`, `insert`, `remove`, `concat`, `sort`, `move_within` and more, with 1-based positions. |
| [Flexible iteration](/guides/iteration/) | `pairs` and `ipairs` that tolerate changes mid-loop, a stateless `next`, and borrowing iterators that never clone. |
| [Shared, nestable tables](/guides/nesting-and-copying/) | Tables are cheap reference-counted handles. Nest them, share them, and copy them shallowly or deeply, cycles included. |
| [Fast by design](/guides/performance/) | Constant-time length, an array part for integer keys, an insertion-ordered hash part, and lookups that never allocate. |
| [No surprises](/guides/error-handling/) | Invalid keys and out-of-range positions return a typed `Error`. The crate contains no `unsafe` code. |

## Prerequisites

These docs assume you are comfortable with basic Rust: ownership and borrowing, `Result` and the `?` operator, and iterators. Familiarity with `Rc` and `RefCell` helps explain why tables behave like shared references, but it is not required to use them.

<Callout title="About the examples">
Every Rust example on this site is compiled and run against the library with `npm run check-samples`, so the `assert_eq!` lines are real results, not illustrations. Examples that use `?` are assumed to sit inside a function that returns a `Result`.
</Callout>
